# MCP Audio Tap (Max for Live)

Master-bus loudness/true-peak meter for the ableton MCP. Drop **MCP Audio Tap**
onto the **Master** track (one-time setup). It serves metering over TCP
`localhost:9878`; the MCP tools `get_audio_tap_status` / `reset_meter` /
`read_meter` / `measure_loudness` read it, and `analyze_set` uses it to evaluate
the loudness/true-peak mastering rules (otherwise deferred as "needs metering").

## Install
1. Ensure Ableton Live **Suite** (Max for Live) is installed.
2. Drag `MCP Audio Tap.amxd` onto the Master track. Leave it enabled.
3. Run `get_audio_tap_status` from the MCP - it should report `connected: true`.

## How it works
- The Max patch applies BS.1770 K-weighting to the master signal and emits a
  per-100ms block of stats (K-weighted mean-square per channel + an oversampled
  true-peak) to the embedded `node.script` (`tap-server.js`).
- `tap-server.js` keeps a reset-able rolling buffer (~1 hour cap) and serves
  `ping` / `reset` / `read` as `{ok,data}` JSON over `localhost:9878`.
- All gating + integration math (absolute -70 LUFS gate, relative -10 LU gate,
  integration, momentary/short-term windows, dBTP) lives in the Python
  `ableton_mcp_max/loudness_utils.py` - the device stays a dumb relay.

## Building / editing the device
`tap-server.js` is the source of truth for the relay; `MCP Audio Tap
(K-weighted).maxpat` is the editable patch source. The shipped `MCP Audio
Tap.amxd` was generated by grafting the measurement chain onto a known-good M4L
device wrapper (the `.amxd` is `ampf`/`meta`/`ptch` chunks around the patcher
JSON; keep the template `plugin~`/`plugout~` + wrapper, swap `boxes`/`lines`).
Signal flow: `plugin~` -> two-stage `biquad~` BS.1770 K-weighting (coefficients
loaded via `loadmess`) -> square (`*~`) -> 100 ms mean-square (`average~ 4800`) ->
`snapshot~ 100`; in parallel `peakamp~ 100` per channel -> `expr max($f1,$f2)` for
peak; all packed into a `block` message -> `[node.script tap-server.js]`.

Live gotchas: Max has no `max` object (use `expr max($f1,$f2)`); two loaded tap
devices collide on port 9878 - keep exactly one; the script-built `.amxd` is more
reliable than pasting the `.maxpat` into the device editor by hand.

## Accuracy notes
- Cross-validated live against iZotope Ozone 12: loudness within <1 LU, peak
  within ~0.1-0.3 dB.
- True-peak is currently **sample-peak** (no 4x oversampling), so it can slightly
  under-read inter-sample overshoots (typically <0.5 dB).
- K-weighting coefficients are the standard 48 kHz set; at 44.1/96 kHz the
  integrated number drifts slightly. The device reports its actual sample rate in
  `ping`/`read`, and `loudness_utils` derives block duration from it.
